# swift-functor

Use this package when you need a structural mapping operation on your own type and would rather derive it than write it by hand. Attach `@Functor` to a struct or enum generic over one element to get a covariant `map`; `@Invariant` to a struct whose element also occurs in input position (for example a stored `(A) -> A`) to get `imap`; `@Traversable` to map with an effect that can fail or suspend; `@Representable` to a fixed product of same-typed coordinates to get an index enum and the conversion to and from a function over it; and `@FunctorBase` to a recursive enum to get its one-layer `Base<Recursive>` functor. To reduce a structure to a summary instead, use `@Foldable` from the sibling swift-foldable.

## Laws

- Every derived `map` satisfies identity (`map { $0 }` is the value unchanged) and composition (two maps equal one map of the composed function). Every occurrence of the element is mapped, including inside arrays, optionals, tuples, nested enum payloads and function results. Stored fields that do not mention the element are carried over unchanged. Static and computed members are ignored.
- `imap(forward, backward)` satisfies identity and composition observationally: `imap(f1, g1).imap(f2, g2)` behaves as `imap({ f2(f1($0)) }, { g1(g2($0)) })`. `forward` is applied in output positions, `backward` in input positions.
- `@FunctorBase` produces a nested `Base<Recursive>` enum with the same cases, in the same order and with the same labels, where each payload of the enum's own type becomes `Recursive` and every other payload is unchanged. `Base` is itself `@Functor`, so its `map` touches the recursive positions only.
- The three traversals visit occurrences of the element in declaration order, depth-first and left to right. A `nil` inside a stored optional is absence, not failure: it is kept as `nil` and is not visited. `traverseOptional` stops at the first `nil` from the transform and returns `nil`; `traverseResult` stops at the first `.failure` and returns it; `traverseSequential` stops at the first thrown error and rethrows it. No element after the stopping one is visited. `traverseSequential` awaits one element at a time and never runs transforms concurrently. A case or structure with no element occurrence succeeds without calling the transform. When every transform succeeds, `traverseResult` yields the same structure as `map`, and `traverseOptional` satisfies identity and composition.
- `@Representable` generates a peer enum named after the struct with an `Index` suffix, with one case per stored field, in declaration order, and `Index` names that same enum for every instantiation of a generic type. `tabulate(value.index)` reproduces `value`, and `tabulate(f).index(i) == f(i)` for every index `i`. `values` is a lazy view in field order, recomputed from `index` on each access and never cached.
- `@Representable` requires all stored fields to have one type, the generic parameter, or the first field's type for a non-generic struct, and allows no initialized `let` constants. A non-generic struct needs at least one field. If the struct declares its own initializer, one of them must assign each parameter directly to the matching field in field order, and `tabulate` calls it with that initializer's argument labels. A validating or transforming initializer is rejected, and that type needs a hand-written representation.
- `@Traversable` accepts a struct or enum with exactly one unconstrained generic parameter. `@Invariant` and `@Representable` accept structs only, and `@FunctorBase` accepts enums only. Any other shape is a compile-time diagnostic, not a runtime failure.
